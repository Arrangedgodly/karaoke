- **Status:** Decided (research complete 2026-08-29).
- **Delegation record:** Researched by deep-research track agent (RQ-3); primary sources: W3C Web Audio 1.1 spec §1.31, MDN WaveShaperNode/oversample/curve, WebAudio spec issue #1943, oversampling/aliasing literature. Full file written to docs/ultron/research/rq3-distortion-curves.md.

## Question

Which WaveShaper curve family and tone-stage design gives a musical **vocal** distortion with Drive/Tone/Output controls and no audible aliasing at max drive? Vocal, not guitar: subtlety at low drive matters. Params FIXED at Drive/Tone/Output; level-guarded; existing limiter (src/node-limiter.js) stays downstream. Web Audio natives only; curve generation in JS; Chrome-only; no build step.

## Constraints / criteria

1. Three params only: Drive (0–1), Tone (0–1), Output (level-guarded).
2. No audible aliasing at max drive (44.1/48 kHz contexts).
3. Subtle warming at low drive (spec itself frames waveshaping as "distortion and other more subtle warming effects" — W3C Web Audio 1.1 §1.31).
4. All Web Audio native nodes (WaveShaperNode, BiquadFilterNode, GainNode). No AudioWorklet needed.
5. Registration shape identical to node-compressor.js: one `registerNodeType` factory + one `NodeTypes.register({label, paramSpec, applyParam})`; param writes ramped via AudioParamRamp (~15 ms) per Issue #5 convention.
6. Curve must be symmetric (or near-symmetric) to avoid DC output — spec note: "The use of a curve that produces a non-zero output value for zero input value will cause this node to produce a DC signal" (§1.31.2, Note).

## Options considered

### A. Curve family

| Option | Verdict |
|---|---|
| **Soft-clip tanh / rational-tanh family** (`y = tanh(k·x)/tanh(k)` or `x/(1+|x|·k)`-style) | **Recommended.** Smooth C∞ curve, near-linear at small |x| (subtle at low drive), gradual shoulder, lowest aliasing energy of the simple families because harmonics roll off smoothly rather than snap. Standard in soft-clip literature and musicdsp recipes. |
| Exponential/abusive folds (e.g., `x·e^(1−x)` shapes) | Rejected — steeper high-order curvature generates more high harmonics per drive unit; harder to keep subtle at low drive. |
| Hard clip (linear then clamp) | Rejected — discontinuous derivative at knee creates broadband harmonics; audible aliasing at max drive even with 4x oversampling; "fuzz" not vocal warmth. |
| Diode-style asymmetric folds | Rejected — asymmetry creates DC and even harmonics ("buzz"); DC must be removed and it fights the spec's DC note; character is guitar-amp, not vocal. |
| Guitar-amp-style multi-stage (pre-gain → shaper → cab lowpass emulation) | Rejected as over-scope; cab-sim-style aggressive lowpass loses vocal intelligibility. The recommended design below keeps its one good idea (post-shaper lowpass) in a vocal-friendly form. |

### B. Oversampling strategy

| Option | Verdict |
|---|---|
| **`oversample = '4x'`** on the WaveShaperNode | **Recommended.** Spec §1.31.2: "A value of '2x' or '4x' can improve the quality of the processing by avoiding some aliasing, with the '4x' value yielding the highest quality." At 48 kHz, 4x pushes generated harmonics up to 4·Nyquist before downsampling, so folded aliases land well above audibility for a tanh curve. |
| `'2x'` | Fallback only; halves alias margin. Adequate at low drive, marginal at max drive. |
| `'none'` + JS pre/post BiquadFilter | Rejected — a linear pre/post filter cannot undo aliasing already generated by the nonlinear stage; oversampling is the canonical remedy (see Nick Writes a Blog; arXiv 2505.11375). Also the spec explicitly warns oversample filters are implementation-tuned for "low aliasing" — something we can't replicate with two biquads. |

Caveat recorded: spec says "The exact up-sampling and down-sampling filters are not specified" (§1.31.2) and GitHub issue #1943 confirms anti-aliasing quality of 4x is implementation-dependent — mitigated here by Chrome-only constraint (single implementation, consistent behavior).

### C. Tone-stage topology

| Option | Verdict |
|---|---|
| **Post-shaper BiquadFilter lowpass, frequency mapped exponentially by Tone** | **Recommended.** One native node; Tone 1.0 → ~11–12 kHz (near-transparent), Tone 0 → ~1.5–2 kHz (dark, radio-ish vocal); exponential mapping matches perception (spec §1.6.2: "Parameters representing filter frequencies… are best changed exponentially because of the way humans perceive sound"). |
| Post-shaper BiquadFilter lowshelf | Viable alternative for a "bass boost" tone feel, but a lowpass is what tames residual high-frequency harshness/alias products after distortion, so lowpass serves both musical and technical roles. |
| One-pole lowpass built from... nothing native — Web Audio has no one-pole; would need IIRFilterNode | Rejected: IIRFilterNode coefficients are fixed at creation, so a Tone slider couldn't move the cutoff without rebuilding the node. Disqualifying for a live param. |

## Recommendation + rationale

**GainNode (drive pre-gain) → WaveShaperNode (normalized tanh soft-clip curve, `oversample='4x'`) → BiquadFilterNode lowpass (Tone) → GainNode (Output, level-guarded).**

- tanh soft-clip is the only family in scope that is (a) near-linear at low input, satisfying "subtlety at low drive", and (b) smooth enough that 4x oversampling suffices for inaudible aliasing at max drive.
- 4x oversample is a one-line, spec-endorsed ("highest quality") aliasing remedy; free in CPU terms for one node.
- Post-shaper lowpass both shapes tone and further buries any residual ultrasonic residue — belt and braces on the no-audible-aliasing criterion.
- Output stage is a plain GainNode feeding the existing downstream limiter; guard computed as below.

## Tradeoffs / risks / confidence

- **Risk: 4x anti-alias quality is browser-specific** (E5). Mitigated: project is Chrome-only. Confidence: high.
- **Risk: oversampling adds small latency** (E1 note). One node, implementation-defined, sub-ms-class in Chrome; irrelevant for karaoke playback. Confidence: high.
- **Tradeoff: curve regeneration on Drive change.** WaveShaperNode copies the curve on set (E2), and (per spec setter algorithm) a second `curve` assignment throws InvalidStateError once a curve was set — implementation must **recreate the WaveShaperNode** on live Drive changes OR bake drive into a pre-GainNode and keep the curve fixed. **Strongly prefer the latter** (fixed curve + drive-in-pre-gain); only Tone (biquad frequency AudioParam) and Output (GainNode AudioParam) are then live-slider-updatable via AudioParamRamp, matching the compressor pattern exactly.
- **Risk: DC from asymmetric curves** — avoided by symmetric tanh family (E2 note).
- **Confidence: high overall** (spec-backed oversampling + well-established curve family); medium on exact Tone Hz endpoints (tuning-by-ear decision for the host, per project philosophy).

## Implementation consequences (concrete)

Signal chain inside the distortion node factory (returned as the node handed to buildGraph; a small wrapper object with `input`/`output` or a chain head/tail as other multi-node types like EQ do):

```
input → driveGain (GainNode) → shaper (WaveShaperNode, curve=tanh curve, oversample='4x')
      → tone (BiquadFilterNode, type='lowpass', Q≈0.0001 (butterworth-ish) or default 1)
      → outGain (GainNode) → (existing downstream limiter unchanged)
```

Curve formula sketch (computed once in JS, N = 1024 or 2048 points, odd length so x=0 maps to center exactly):

```js
const N = 2047;                 // odd → exact center at 0 per E2
const curve = new Float32Array(N);
for (let i = 0; i < N; i++) {
  const x = (i / (N - 1)) * 2 - 1;      // [-1, 1]
  curve[i] = Math.tanh(x * 1.5) / Math.tanh(1.5);  // normalized: f(1)=1
}
shaper.curve = curve;
shaper.oversample = '4x';               // E1
```

**Drive mapping (no curve regeneration):** Drive 0–1 → `driveGain.gain = 10^(drive * 2) / 10^(0) `-style; concretely linear gain from 1.0 (drive 0, near-transparent since tanh is near-linear for |x|<0.3) to ~+20 dB (drive 1). Ramp via AudioParamRamp.

**Tone mapping:** Tone 0–1 → `tone.frequency = 1500 * (12000/1500)^tone` (exponential sweep 1.5 kHz → 12 kHz, E8). Ramp frequency param (setTargetAtTime/linearRamp via AudioParamRamp).

**Output guard:** outGain.gain = `10^(outDb/20)` clamped so the stage cannot boost past unity + makeup consideration: since the tanh curve is normalized to ±1, worst-case shaper output peak is 1.0 regardless of drive; guard = clamp Output slider to ≤ 0 dB default (1.0) and compute `outGain = Math.min(outGainParam, 1.0)` — the existing downstream limiter stays as final safety net. If a makeup-style boost is ever allowed, cap at +6 dB and document that the limiter catches peaks.

**Param spec (NodeTypes.register):** `drive` {0..1, default 0.25}, `tone` {0..1, default 0.7}, `output` {dB −24..0, default −3 or 0}. applyParam writes ramped values to driveGain.gain / tone.frequency (after exponential map) / outGain.gain respectively. Node creation sets initial values directly (same convention as compressor factory).

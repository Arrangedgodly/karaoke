## Design Specificity Verdict

**LLM assessment: genuinely authored, product-specific — not category-interchangeable.** The touring-rack metaphor is carried end-to-end with rare discipline: silkscreen micro-labels vs mono LCD readout register (title 12px silkscreen vs mono machine values), family legend squares with silkscreen initials (GN/CP/EQ/DL/RV/LM) so color is never the only signal, split-role safety red (edge ring when OFF, fill when ON — the two roles never swap), amber restricted to the machine's voice, shadows only on physical lift, and fixed-width tabular-nums slots so "—" becoming "48.0 kHz" changes glyphs, never geometry. An unrelated product could not reuse this surface unchanged. Weak spots in character: the working-title legend is generic by binding constraint; "AGENT —" reads as a broken placeholder to unanchored eyes; and amber fader caps on every param dilute the Amber Voice Rule the system itself declares.

**Deterministic scan:**
- CLI full-parser scan (detect.mjs, temp copy with parser deps installed): **7 findings, exit 2** — 3× undersized functional text (RATE, LATENCY, NODES at 10px), plus overused-font (roboto), flat-type-hierarchy (ratio 1.7:1), side-tab accent border, repeating-gradient stripes.
- Browser overlay injection (succeeded; fresh automated tab): **15 findings** — 5× undersized text (RATE, LATENCY, NODES, CLIP, live dB readout "−5.7" — all 10px), 6× border-accent-on-rounded (all six node cards), 1× wide letter-spacing (agent chip sr-only text), overused-font roboto/arial share, flat-type-hierarchy, and **2× text-occlusion: the OUT anchor is 50% covered and the safe-output note 47% covered by overflowing node cards — verified real by geometry probe and screenshot (see Priority Issue 1).**

**Detector caught what the review missed:** the occlusion defect. The design review walked the source and the screenshots but did not compute overlap geometry; the detector's text-occlusion rule found it, and adjudication (flex `min-height: 1.5rem` on `#chain-list` lets it shrink below content inside the bounded VIS-7 canvas; positioned `.node-card`s paint over the static anchor) confirmed a genuine default-state layout bug, not a scroll-clip artifact.

**Review caught what the detector cannot see:** the param-vocabulary wall for a non-engineer, the dead-end error path, the pre-Start affordance dishonesty, the absent bypass reflection on the canvas, the emotional-journey valleys.

**False positives (with reasoning against DESIGN.md tokens):** overused-font "roboto" — the font stack is the platform system stack (`system-ui, …, Roboto, Helvetica, Arial`) mandated by the offline/no-webfonts constraint; roboto is a fallback name in computed styles, not a chosen face. wide-tracking on the agent chip — flagged on an `.sr-only` span (invisible text; the tracked silkscreen register on visible labels is the design system itself). border-accent-on-rounded ×6 — the 3px family top edge IS the ratified core encoding ("family color as edge marking, never fill," redundant with legend square + text label, a deliberate guitar-pedal-world donation); the detector pattern-matches the AI-slop side-tab, but here the border carries verified, documented, redundantly-encoded meaning. repeating-gradient stripes — the fader detent ticks (1px hairline marks every 12px), a functional skeuomorph rather than surface decoration; partially fair as noise at current size. flat-type-hierarchy — true in size-only terms (10–16.8px), but the hierarchy is deliberately carried by register (mono vs silkscreen), weight, and color, per the two-register rule; the honest residue is that the smallest sizes are genuinely too small (see Issue 4).

**Visual overlays:** injection succeeded in an automated tab — `impeccable-overlay` elements rendered in the page and the console reported "[impeccable] 15 anti-patterns found." No user-visible **[Human]** tab exists in this run: the harness-native browser tool is unavailable in this subagent session, so overlays were verified in a fresh headless automated tab driven via playwright-core + system Chrome (screenshots archived in-context for the run), not presented live.

## Overall Impression

A genuinely authored dark pro-audio console — the redundant-encoding discipline, the status-LCD strip craft, and the safety choreography are well above the norm for a vanilla-JS single page. Three things undermine it where it hurts most: a default-state layout defect that buries the OUT meter under effect cards, a total absence of plain-language help for the one user who runs it live under pressure, and an error path that names failures but teaches no recovery. The single biggest opportunity: make the machine's state and vocabulary readable by someone who has never heard the word "compressor."

## What's Working

1. **Redundant encoding discipline.** Family color always pairs with legend-square initials and a text label; clip state is triple-encoded (red pin + dot + text); refusal tone comes from a bezel, never failing-contrast red text. Color is never the only signal anywhere — verified in source and in the live DOM.
2. **The status LCD strip.** Fixed-width tabular-numeral slots that never pump layout when values arrive, an ellipsizing error line, machine cluster wrapping below 900px so BYPASS never leaves the visible row, and BYPASS sized/louder-by-rule (3rem, 1.05rem/700 type, red ring). This reads as broadcast rack gear, not a web header.
3. **Safety choreography.** Gated-until-start (visually and functionally double-guarded), spacebar bypass that works wherever focus is, watchdog force-mute with human-only Restore, and agent mutations that land as summary toasts with one-click undo. "The show comes first" is implemented, not just written down.

## Priority Issues

1. **[P1] Effect cards visually bury the OUT anchor, its meter, and the safe-output note in the default live state.**
   Why it matters: with the default Classic Karaoke preset expanded on a 1440×900 laptop viewport, `#chain-list`'s explicit `min-height: 1.5rem` lets the list shrink below its content inside the bounded VIS-7 canvas; the overflowing (position:relative) cards then paint over the static OUT anchor — the detector measured 50%/47% occlusion and screenshots confirm the OUT block and even the FLOW toggle are invisible until cards are collapsed. The OUT meter is the operator's one-glance output-health check from across a dark room, and the watchdog Restore banner appends into the same buried region — a safety element can literally render underneath effect cards mid-show. Collapsing all cards clears it (all-collapsed geometry: no overlap), which proves it is a layout defect, not a scroll behavior.
   Fix: stop `#chain-list` from shrinking below content (e.g. `flex-shrink: 0` / `min-height: auto` in the vertical flow), keep anchors in normal flow so the canvas scrolls as intended, and audit stacking (positioned cards vs static trailing siblings) plus the watchdog alert's insertion point.
   Suggested command: `$impeccable layout`

2. **[P1] The parameter vocabulary has no plain-language layer for the non-engineer who runs the show.**
   Why it matters: PRODUCT.md's primary at-risk user "does not know signal-engineering vocabulary," yet the surface's only adjustment granularity is Threshold/Ratio/Attack (in raw seconds like 0.01 s)/Release/Ceiling/Feedback/Mix in dB, %, ms — with no tooltips, hints, or glossary anywhere. Mid-show, "make it less echoey" has no visible path; the natural-language agent route exists only when WebMCP is present, and the chip says "AGENT —" most of the time.
   Fix: add a one-line plain-language hint per param (hover + focus + long-press): "Mix — how much echo you hear", "Threshold — how loud before squashing starts". Frame the five riskiest params in outcome language; the mono value register stays untouched.
   Suggested command: `$impeccable clarify`

3. **[P1] Error states leak raw exceptions and teach no recovery.**
   Why it matters: the single most likely live-show setup failure — mic permission denied — surfaces as "Failed to start (Permission denied)" in the status line, with Start re-enabled but zero guidance to the Chrome mic-permission path; device-switch failures behave the same. For the brother, this is a dead end at doors-open; heuristic 9 exists precisely for this moment.
   Fix: map known DOMException names to operator-voice sentences plus a next action ("Mic was blocked. Click the camera icon in the address bar → Microphone → Allow, then press Start again."), keeping the technical string as a small footnote for the developer persona.
   Suggested command: `$impeccable harden`

4. **[P2] Text renders below the design system's own 11px floor in its two most distance-critical registers.**
   Why it matters: RATE/LATENCY/NODES micro-labels and the meter dB readouts (incl. the CLIP latch) all render at 0.625rem = 10px — violating DESIGN.md's 11px Floor Rule ("distance legibility is a product requirement") — and the detector independently flagged all five instances. These are exactly the registers meant to be read at two meters in a dark venue. (DESIGN.md is itself internally inconsistent, listing 0.625rem in its hierarchy while declaring 0.7rem the floor.)
   Fix: raise both to 0.7rem minimum, widen the fixed readout slots to match, and reconcile the DESIGN.md hierarchy text with its own floor rule.
   Suggested command: `$impeccable typeset`

5. **[P2] The pre-Start gated state is affordance-dishonest.**
   Why it matters: before Start, the empty-hint teaches "Drag an effect here to start building your chain" while the palette is pointer-events:none, and the 0.55 dimming is ambiguous — an unanchored viewer read both flanks as "fully functional"; the only true instruction on the whole surface is the device select's placeholder ("-- click Start to list devices --"). Every session (both personas) passes through this state; the portfolio first impression and the brother's setup both start with an impossible invitation.
   Fix: make the hint state-aware ("Press Start to power on" pre-Start, the drag copy after), add a clearer inert treatment (not-allowed cursor, stronger dimming or a lock seam on the flanks), and keep one visible instruction anchored to the Start control.
   Suggested command: `$impeccable clarify`

## Persona Red Flags

**Alex (Power User)** — no keyboard path to add or reorder nodes (palette chips are non-focusable divs; SortableJS drag is pointer-only); no numeric entry on faders (Attack's 0.001 s steps are mouse-only); no duplicate-node action; collapse state resets on every preset load or agent mutation (documented v1, still annoying mid-tuning); Save As… uses a blocking native prompt.

**Sam (Accessibility-Dependent)** — sliders are keyboard-operable with a clear 2px focus ring (verified), and chevron/×/grip carry aria-labels, but node ADDITION is unreachable by keyboard or screen reader (chips are divs with no role/tabindex); the status lamp/text has no aria-live, so "Live"/"Failed" transitions are silent to assistive tech (only the toast region announces); the grip's affordance is hover-title-only.

**Marco, the brother (project persona from PRODUCT.md: non-engineer, dark venue, laptop + PA, mid-show)** — red flags at exact elements: param labels "Threshold −24 dB", "Attack 0.01 s", "Ratio 4:1" (no plain-language layer anywhere); the buried OUT meter + "Safe output: ON, ceiling −6 dBFS" note under stacked cards; "LATENCY 47.8 ms" occupying a prime strip slot he cannot act on; "Failed to start (Permission denied)" with no next step; "AGENT —" chip that reads as broken; 10px meter numerals at two meters; a native "Save chain as:" browser prompt mid-show; two "Classic Karaoke" entries (Factory + Yours) in the preset dropdown with no distinction but group membership.

## Minor Observations

- `window.prompt` (Save As…) and `window.confirm` (delete) break the no-modal console vocabulary and render light-native in a dark theme.
- Bypass engaged is invisible below the topbar — the deferred canvas dimming (documented in src/main.js as out of scope) means mid-show confirmation of the safety state rests on one 48px button. Candidate for promotion to P2.
- Post-Start, the disabled amber Start button reads as a contradiction ("LIVE but Start is dead?") to fresh eyes; a spent/"Running" state would close the loop.
- Amber fader caps on every param dilute the amber voice the system reserves for action/machine attention.
- Detent ticks (repeating hairline gradient) read as noise at the current track size — the detector's "stripes" flag is a false positive, the noise observation is fair.
- Two 404 resource errors appear in the console on a fresh profile load (favicon-class noise) — cosmetic, but a portfolio visitor with devtools open sees red.
- "AGENT —" (unavailable state) reads as a placeholder/broken; consider hiding the chip entirely in that state (the design says "indistinguishable from today's app" is the goal when WebMCP is absent).
- The preset dropdown shows factory and user presets with identical names ("Classic Karaoke" twice) — namespaced correctly by optgroup, but the duplicate label invites mis-load under pressure.
- Collapse state is session-only and resets on preset/agent loads — documented accepted v1 behavior; worth one sentence of in-app communication if it survives.
- The FLOW: VERTICAL toggle floats under the scrolling canvas; its affiliation (canvas control vs panel chrome) is ambiguous.
- Native select option rows render at 10px on Chrome/macOS — below the floor, out of the theme's reach without custom rendering.

## Questions to Consider

- If the operator can only do ONE thing mid-show, why does the pre-Start screen advertise anything else before Start is pressed?
- What would this console look like if every param label had to be understood by someone who has never heard the word "compressor" — and is the agent the answer, or is plain language the answer the agent cannot always give?
- The OUT block is the operator's ground truth for "is my sound healthy" — should it be the most immovable thing on the canvas rather than the last thing in a shrinkable column?
- Should the LATENCY register keep its slot on the strip if the person it matters to most is the developer, not the operator?
- When bypass is the show-saver, why is its engaged state confined to a 48px button while the canvas below pretends nothing changed?

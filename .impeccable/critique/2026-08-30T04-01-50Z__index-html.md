## Overall Impression

Cycle 3's engineering discipline held every safety invariant (pinned footer, zero primary-flow dialogs, occlusion-free canvas at 10 cards, single-source experimental disclosure), and PR #17's toast truthfulness is genuinely good interaction design. The score dip is entirely polish-layer debt on the new surface area: the four new effects shipped without the plain-language layer that fixed run 1's worst finding, the safety-relevant EXP badge breaks the system's own type floor, and the palette doubled to ten ungrouped options. The single biggest opportunity: give the new effects the same operator legibility the original six earned.

## What's Working

1. **Single-source experimental disclosure.** `experimental: true` at registration flows to the card badge, the chip's aria-label suffix ("Add Autotune to chain (experimental)" — heard BEFORE the node exists), and the agent capabilities readout; the visible badge and agent-facing truth cannot drift.
2. **The param select is a native semantic in costume.** Arrow keys, typeahead, and SR value announcement for free; mono readout register at the 11.2px floor; the fader row rhythm intact — verified live (widths 88/96px, values C/Major, no header wrap).
3. **PR #17's truthful toasts.** Failed restores keep their entry, name the error, and say "retry Undo"; conflicted undos demand an explicit "Undo anyway"; recovery toasts outlive the 6 s toast; the shared active-toast lookup keeps exactly one Undo button on the newest live toast.

## Priority Issues

1. **[P2] The four cycle-3 families ship with zero plain-language help.**
   Why it matters: PLAIN_LANGUAGE_HELP covers gain/compressor/EQ/delay/reverb/limiter only (verified: row.title null on every gate/distortion/chorus/autotune param). PRODUCT.md's at-risk operator meets "Floor −40 dB", "Retune Speed 0 ms", "Depth 3 ms", "Drive 0.25%" with no aid — the exact wall run 1's P1 fix tore down, rebuilt for the new effects.
   Fix: extend the map in src/param-controls.js (~14 lines, README voice, outcome-framed direction clauses for the risky ones — gate Threshold/Floor, distortion Drive/Output, autotune Retune Speed).
   Suggested command: `$impeccable clarify`
2. **[P2] The EXP badge renders at 10px, below the design system's own 11px floor.**
   Why it matters: computed 10px on both placements (chip + card); the detector flagged both; the CSS comment claims "above the 11px card floor at 0.625rem" — 0.625rem IS 10px — and DESIGN.md documents the same contradiction. This is the same self-inconsistency cycle 1 fixed for RATE/LATENCY/NODES, now on the one tag that discloses experimental DSP status — text that matters most read at two meters.
   Fix: raise to 0.6875rem (the initials' size), widen the tag padding to compensate, and correct both the CSS comment and DESIGN.md's component spec.
   Suggested command: `$impeccable typeset`
3. **[P2] The add-a-node decision point is now 10 flat, ungrouped options.**
   Why it matters: the palette went 6 → 10 chips with no grouping (verified live); the working-memory rule calls 8+ overloaded, and the cognitive-load checklist fails chunking/minimal-choices. At setup time under pressure, the brother scans a wall of ten equal-weight chips where six was already dense.
   Fix: silkscreen group headers in the flank (e.g. the original six vs. the cycle-3 four, or dynamics/time/pitch groupings) — palette stays registry-driven; the grouping is a presentation seam.
   Suggested command: `$impeccable layout`
4. **[P3] Distortion's Drive/Tone display breaks the surface's % convention.**
   Why it matters: 0–1 values with unit "%" render "0.25%"/"0.7%" (DOM-verified) while Mix on the same card reads "30%" — a non-engineer reads a quarter of a percent where the fader means a quarter of full drive.
   Fix: either scale the display to 0–100 (25%) or drop the unit and keep the raw 0–1 with no % sign; one consistent convention surface-wide.
   Suggested command: `$impeccable polish`
5. **[P3] Standing guards and edges.**
   Why it matters: +24 dB gain and mid-show limiter removal remain unguarded (standing P2 from run 1, unfunded); two window.alert survive in presets-ui defensive paths; a context that resumes after start completion leaves the strip wedged at "Stopped" (handleContextState only corrects when contextLost was set — observed in the live run).
   Fix: loud-path confirmation vocabulary, route the two defensive paths through the quiet .preset-note line, refresh the status sentence on every context running transition.
   Suggested command: `$impeccable harden`

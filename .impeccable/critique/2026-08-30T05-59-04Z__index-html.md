## Priority Issues

1. **[P3] Agent-facing display seam: get_capabilities publishes distortion drive/tone as {unit:'%', range:[0,1]} while the operator surface reads 0–100%.**
   Why it matters: an agent asked for "50% drive" sends 50, is rejected with the [0,1] range inline, and corrects in one round trip — deliberate and documented, but it is the system's last two-scales-for-one-number inconsistency, now purely agent-side.
   Fix: either scale the published range to [0,100] to match the readout (accepting values in both scales transiently), or keep 0..1 and say so in the param's action note ("values are 0..1 = 0–100%").
   Suggested command: `$impeccable polish`
2. **[P3] get_capabilities serializes to 2,487 chars (live-measured), above the ~1.5k Chrome guidance the PR targeted.**
   Why it matters: agent-facing only and 6× smaller than the >15k it replaced; every cycle-3 disclosure (experimental map, discrete value lists, chain rules) is preserved. The miss is real but consequence-light.
   Fix: drop the `app` field and shorten the experimental note / chain-rule phrasing to reach ~1.5k, or accept 2.5k as within tolerance for a one-time read.
   Suggested command: `$impeccable distill`
3. **[P3] Autotune's Key help line is ~200 characters (experimental status + 20 ms disclosure + key guidance) on a native title tooltip.**
   Why it matters: one said-once-per-card line is the right disclosure discipline, but native tooltips truncate awkwardly around that length and screen readers announce it in full on every Key focus.
   Fix: keep the Key line about the key; move the experimental + 20 ms disclosure to the badge's own aria/title so it is still said once per card, at the badge.
   Suggested command: `$impeccable clarify`

# Tone.js FX conversion — contract-preserving, phased

## Goal

Make adding effects cheap (thin registration on top of Tone.js instead of hand-built Web Audio plumbing per effect) without breaking the WebMCP layer (PRs #17/#18/#19). Scope per your choices: adapter + 4 new effects (pitch shift, tremolo, bitcrusher, phaser) + migrating existing effects where it pays off + additive sound-design-guide vocabulary.

## Why this is safe for the WebMCP work (the core finding)

The MCP layer never touches DSP. It binds to two registries, and everything your brother built reads them dynamically:

- `add_node`'s type enum, `set_param` validation, capabilities readout, palette chips, and preset serialization all come from the **live** `NodeTypes` registry (`registryTypes()` in src/mcp-tools.js:470 — live wins, static `NODE_REGISTRY_SNAPSHOT` is only a fallback for bare test harnesses).
- The `set_param` fast path calls `AudioGraph.updateNodeParams()` + `NodeTypes.applyParam()` + `ChainCanvas.updateNodeParam()` — all preserved untouched.
- `SOUND_DESIGN_GUIDE` references **param ids/units/ranges**, not implementations. As long as migrated effects keep their paramSpec identical, the guide stays truthful.

So the compatibility contract is: **type strings and paramSpecs (id/min/max/default/step/unit/values) stay byte-stable; the factory/applyParam signatures stay the same; only the internals behind them change.**

## Architecture

**1. Vendor Tone.js** — `vendor/tone.min.js` (UMD build, pinned 15.x, ~1MB local — fine over localhost; repo has no build system, Sortable.js precedent). Add `<script>` after `src/audio-graph.js` (before node files). Add MIT entry to `THIRD_PARTY_NOTICES.md`. Spike check first: confirm the UMD exposes `window.Tone` with `Tone.connect()` native-interop and `Tone.setContext()`; if 15.x has no UMD, fall back to the ESM build loaded via a deferred module script (safe because node files only *register* at parse time; Tone is first touched at graph-build time, which is always after a user click).

**2. New file `src/tone-adapter.js`** (~200 lines, ES5 IIFE, `window.ToneAdapter`):
- `ToneAdapter.register(type, config)` where config = `{label, experimental?, create(audioContext, params) → Tone node, paramSpec: [...same shape as NodeTypes], applyParam(toneNode, composite, paramId, value)}` — one call performs **both** `AudioGraph.registerNodeType` and `NodeTypes.register`. This is the payoff: a new effect becomes a ~60-line config file.
- Factory: lazily `Tone.setContext(audioContext)` (compares `Tone.getContext().rawContext` — handles first build and context recreation after session teardown; device switches reuse the context, verified). Wraps the Tone node in a composite `{input: GainNode, output: GainNode, tone, dispose()}` wired with `Tone.connect(input, toneNode)` / `Tone.connect(toneNode, output)` — satisfies the existing AE-7 composite contract, so `buildGraph` needs zero changes to connect them.
- Param writes: `toneParam.rampTo(value, 0.015)` (Tone's click-safe ramp, equivalent to the existing 15ms `AudioParamRamp` convention); hybrid composites that keep native AudioParams still use `AudioParamRamp.schedule`.
- Defensive: registration must not require `window.Tone` (vm harnesses without Tone must still load it); only factory invocation may fail, with a clear error.

**3. Dispose hook in `audio-graph.js` teardown** — one guarded addition: when a replaced/removed instance has `.dispose()`, call it (try/catch). Tone effects with internal LFOs (tremolo, chorus, phaser) leak CPU if only their output node is disconnected. No-op for every existing type (plain AudioNodes/composites have no dispose) — zero behavior change.

**4. New effects** — each a small `src/node-*.js` registration file, `experimental: true` (existing badge mechanism), params chosen to demo well via plain language:
- `pitchshift` (Tone.PitchShift): `pitch` −12..12 semitones, `mix` %
- `tremolo` (Tone.Tremolo, needs `.start()` for its LFO): `rateHz`, `depth` %
- `bitcrusher` (Tone.BitCrusher): `bits` 1..8, `mix` %
- `phaser` (Tone.Phaser): `rateHz`, `depth` %, `baseHz`

Palette: they appear automatically under the "More effects" fallback group; optionally add explicit `PALETTE_TYPE_GROUP` entries (canvas.js:1229) — additive.

**5. Guide + MCP polish (additive only)** — new `SOUND_DESIGN_GUIDE` entries (e.g. `dreamy: phaser…`, `crystal: pitchshift…`, `warble`/`lofi`) following the c2ff76c convention: reference real param ids/units/ranges. All existing entries byte-identical. No `AGENT_PARAM_POLICY` entries needed (absence falls back to paramSpec ranges, verified at mcp-tools.js:1765).

**6. Migration of existing effects — one per commit, with a go/no-go gate** on the first one. Keep type + paramSpec identical; rewrite only the factory/applyParam internals:
- **Migrate**: `delay` (FeedbackDelay), `compressor` (Compressor), `eq` (EQ3 — set lowFrequency 200 / highFrequency 5000 to preserve current response), `chorus` (Chorus: depthMs→depth mapping, rateHz→frequency), `distortion` (hybrid: Tone.Distortion inside the existing tone-lowpass/output-gain stages), `reverb` last (Tone.Reverb loading the same `assets/ir/plate-vocal.mp3` IR via the existing async fetch/unity-passthrough splice pattern).
- **Stay native regardless**: `gain` (12 lines, nothing to gain), `limiter` (safety-critical, host-owned, watchdog-entangled), `gate` + `autotune` (worklet DSP with no Tone equivalent — Tone.PitchShift ≠ scale-snapping autotune).
- **Honest trade-off, stated now**: these six are *lateral* moves DSP-wise (Tone wraps the same Web Audio primitives). The value is consistency + deleting ~1,300 lines of hand-rolled plumbing; the cost is rewriting their structure tests and retiring their offline-render QA coverage. Sequencing migration last means you can evaluate cost/benefit on the first one (`delay`) and stop there if it isn't worth it.

## Do-not-break invariants (checked at every step)

1. Existing 10 type strings + paramSpecs byte-stable; all 10 MCP tool names/schemas unchanged.
2. Existing `SOUND_DESIGN_GUIDE` entries byte-stable (tests assert them); additions only.
3. `set_param` fast path invariants: same physical instance reused, zero `buildGraph` calls.
4. Old presets/autosaves still load (paramSpecs unchanged ⇒ `PresetSchema.deserialize` unaffected).
5. Two-phase rebuild, chain-gate duck, bypass tap, watchdog, meters untouched (except the guarded dispose hook).
6. Suite green (`node tests/run.js`, currently 30/2313) at every commit; checks added, never silently dropped (per-effect structure tests for migrated effects are rewritten in place, keeping their MCP-level assertions).
